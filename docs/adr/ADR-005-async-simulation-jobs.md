# ADR-005 — Async simulation jobs

Status: accepted as a product boundary; implementation partial. Date: 2026-09-27.

2D/3D solves execute outside Fastify request handlers. A request validates a versioned case and creates a queued job; a worker owns execution, heartbeat, cancellation, bounded retries, resource limits and artifact publication. The API exposes status, failure detail and results by job identity. Existing synchronous 0D and restricted 1D paths remain within their declared limits.

Implementation update (2026-09-28): PostgreSQL stores validated input snapshots with normalized SHA-256 identity, atomic queue claims, expiring leases, heartbeat renewal, cancellation, expired-lease recovery and a single-child bounded retry lineage. Fastify exposes owner-scoped status, cancel, retry and field-artifact routes with role checks and byte-hash verification. Creation and retry require an explicitly injected, version-compatible solver admission; the production app has none. The separate spatial worker bounds its asynchronous wait even if an executor ignores abort, but terminating blocked native solver processes requires an executor/deployment boundary. No cell PDE solver, production field store or deployment CPU/memory isolation is registered, so spatial execution remains unavailable.

Implementation update (2026-09-30): The worker emits structured claim, progress, completion, failure, cancellation and lease-loss events. Known sidecar timeouts, process exits, invalid protocol responses and artifact-integrity failures map to stable persisted failure codes and safe messages; low-level stderr and host paths are not persisted. Development Darcy and Stokes worker/API paths run through the pinned native toolchain in CI. Product solver admission, durable production storage and deployment CPU/memory limits remain pending.

An in-request solve would tie numerical runtime, memory and request timeout to a web worker. A detached process without persisted job state cannot reliably recover or explain a failed run. Gate: durable lifecycle and exactly identified results across restart, cancellation and failure, plus auth and resource tests. Queue technology is undecided.

Batch integration (2026-09-30): SIGINT/SIGTERM abort the active executor and stop new claims and poll waits. An interrupted owned claim records a sanitized `worker_shutdown` failure, preserving the controlled retry lineage; it is not an owner cancellation. The worker waits for its in-flight heartbeat before disconnecting persistence. A shutdown during an asynchronous claim is handled before invoking the solver. Configuration rejects malformed and out-of-range values before database initialization. Library exports no longer start the CLI. Native CPU/memory deployment enforcement remains a separate gate.

The resource-bounded container transport removes the native-test shell shims and is shared by both development executors. Image/resource configuration is trusted worker configuration, never scientific input or API admission. The job persists a distinct sanitized failure if the container cannot be confirmed removed. Local fake-Docker transport tests verify the exact invocation and cleanup after success, process failure, timeout, cancellation, invalid protocol data and daemon cleanup failure; pinned native worker/API CI verifies the real isolated path.
