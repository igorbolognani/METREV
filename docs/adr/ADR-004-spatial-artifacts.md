# ADR-004 — Spatial result artifacts

Status: proposed. Date: 2026-09-27. Implementation update: 2026-09-30.

Persist run identity, input hash, model/runtime version, status, summary metrics, field manifest, units, coordinate frame, provenance and access policy in PostgreSQL. Store large mesh and field arrays in an external artifact store with content hash and an immutable manifest. The existing JSON case result can hold small sampled 1D series but must not contain full 2D/3D fields.

Evaluate XDMF/HDF5 or another documented mesh/field pairing against visualization, parallel output, version compatibility, object storage and reproducible reload. Database blobs and unversioned file paths are rejected as a default for large runs.

`packages/spatial-artifact-store` implements development-only local filesystem adapters for planar `msh4` meshes and HDF5 fields. They hash and size-check bytes, persist immutable content-addressed objects and owner-scoped manifests with private permissions, and verify identity on reload. The authenticated spatial API streams field bytes only after run ownership checks and independent hash/size verification. `spatial-simulation-result-v2` defines compact domain, mesh, field, unit, statistic, conservation, convergence, warning and artifact-hash metadata; field arrays remain external. It binds scalar summaries to their named field statistics and checks integral units against spatial measure. Stokes now exports finite-element pressure and velocity summaries plus direct PETSc termination data; the development worker maps those outputs to result-v2 and owner-scoped artifacts. Darcy transport is verified through the pinned native worker/API path; Stokes has focused worker/API coverage and its pinned native worker roundtrip is the next gate. Version 1 snapshots remain readable, while new input-bound results use version 2. These are development prerequisites, not a selected or deployed production field provider. A production object store and viewer remain pending.

Gate: write, hash, reload, authorize and visualize one verified spatial field while preserving metadata and failure behavior. Local mesh and field adapters, owner-scoped API access, and native Darcy worker/API field integrity are covered. The production provider and viewer remain unverified, so the full gate is not satisfied.
