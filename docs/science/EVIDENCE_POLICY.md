# Evidence, corpus and model coverage

The focused search configuration has 20 queries across OpenAlex, Crossref, and Europe PMC. A target of 500 is a planning budget, not a downloaded or validated corpus. With 20 queries and 3 providers there are 60 query/provider slots; distributing 500 with one-page integer limits assigns 8 records per slot, so the theoretical request ceiling is 480 before duplicates, empty responses, access checks, or review. The checked-in curated manifest has ten source records and ten claims, all pending human review; each source is DOI-traceable, no claims are accepted, and no supplier documents are included. It is a small, hand-curated candidate register rather than a validated evidence corpus.

The `/modeling` workbench joins a live component-linked SVG, a fidelity register, and the quantitative component-property catalog. The SVG updates as a system, architecture, electrode, separator, or model fidelity is selected. Selecting a component opens its declared values with units and source references; a completed run maps modeled observations back to the related component. The drawing is conceptual and not a geometric mesh.

The model catalogs separate four case-runner scenarios (MFC and MEC, each with continuous-flow and closed-batch boundaries), a restricted steady 1D cell marked `case_runner_development`, and research-only options for 1D biofilm depth, 2D electrode/biofilm fields, 3D cell multiphysics, macro-scale cell networks, micro-scale porous electrodes, and nano-informed catalyst interfaces. A 1D selection without a complete `mechanistic_model.cell_1d` returns `insufficient_data`; a complete matching case executes with informational development outputs. The analyst API also accepts the complete 1D input at `POST /api/modeling/coupled-cell-1d`. Research profiles cannot produce a simulation. The catalog supplies no scientific parameter values; every required input still needs its unit and source reference.

`stack_blocks.component_model_parameters` stores source-backed numerical properties for reactor geometry, anode/biofilm, cathode/catalyst, separator, electrical contacts and seals, balance of plant, sensors, and operational biology. The runtime validates catalog identifiers, units, bounds, and provenance. The 0D solver does not silently consume properties that belong to unresolved spatial profiles; requesting a research profile returns the outstanding requirements instead of falling back to the 0D model. Public explanations live under `/learn/[topic]`, including the stack architecture/literature route at `/learn/stack`.

Journal labels are stored only as contextual metadata. Historical CAPES Qualis Periódicos used journal strata for a specified area and cycle; CAPES guidance for 2025–2028 shifts to article-level procedures, with area-specific methods and possible A1–A8 strata. Neither system is a universal international A1–A4 scale, and a journal/article label does not validate a study or an individual claim.

The narrative and research-extraction LLM adapter supports GPT-6 through the OpenAI Responses API when explicitly enabled. The default remains the local deterministic stub (`METREV_LLM_MODE=stub`); opt in with `METREV_LLM_MODE=openai` plus `OPENAI_API_KEY` (or `METREV_LLM_API_KEY`). The default model is `gpt-6-sol`; configure `METREV_LLM_MODEL`, `METREV_LLM_BASE_URL`, and `METREV_LLM_REASONING_EFFORT` when needed. Responses use `store:false`. OpenAI receives the bounded case or source text supplied to that feature, so enable it only when that transfer fits the project's data policy. Generated prose is explanatory; extracted evidence is a candidate checked against the supplied source span and still needs human review. An LLM never assigns source acceptance or model validation.

The focused plan-only run reports 60 planned slots and the backfill dry-run queues zero jobs. The checked-in source registers are versioned repository artifacts, separate from PostgreSQL; this checkout did not inspect prior or remote database contents.

The checked-in candidate registry is separate from the curated manifest. It currently holds twelve traceable source candidates, nine local artifacts (six original and three reproducible numeric extracts), and twenty-six reported-claim candidates. The original first-pass screen covers eight sources and six local files, with source-side arithmetic and file-shape findings recorded in the registry; it did not mark any claim as human-reviewed or decision-eligible, and it did not add to the curated manifest. Four newer paper candidates record formulation, geometry and access limits but are pending review. The staged candidates include open MFC wastewater results with a reported air-cathode leakage failure mode, open MFC biosensor studies with real urban wastewater, MFC/MEC datasets, and a public patent metadata candidate. The CORA MEC extracts preserve 39,540 current-density/LSV values and 290 EIS pairs, including the observed part of an incomplete trace; they are component-characterization candidates, not full-cell validation. Their licenses, locators, local file sizes, and SHA-256 hashes are audited by `metrev:doctor`; none is human-reviewed or eligible for decision inputs. [OpenAlex](https://help.openalex.org/api/) discovers scholarly works and their relationships, and can expose open-access locations; basic search is public and an API key is optional for higher usage limits. [Crossref](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) supplies DOI registration metadata deposited by publishers and trusted sources. [Europe PMC](https://dev.europepmc.org/RestfulWebService) specializes in life-science records and provides metadata plus full-text XML for eligible open-access items. These services help locate sources; they do not by themselves supply compatible, reviewed measurements. Open research-data repositories such as [Dataverse](https://guides.dataverse.org/en/6.8/api/) and [Zenodo](https://developers.zenodo.org/) expose dataset records and files; [Mendeley Data](https://data.mendeley.com/api/docs/) also offers a public dataset API. Patent search can start with [Espacenet](https://worldwide.espacenet.com/) and EPO's [Open Patent Services](https://www.epo.org/en/searching-for-patents/data/web-services/ops). All files still need license, method, units, cell/sample, and applicability review. Repository and patent providers are not yet connected to the runtime ingestion adapters.

The two research bootstrap/queue commands and three individual provider commands below are dry-runs: they only plan work and make no provider or database calls. The provider commands' `--dryRun` flag prints an offline request plan; it never fetches provider records or opens PostgreSQL. `metrev:doctor` is offline by default. Its optional `--probe-providers` mode sends one small read-only metadata search to OpenAlex, Crossref, and Europe PMC to test actual connectivity; it does not download full text, ingest records, or access PostgreSQL. The provider scripts use Node's built-in environment-proxy support when available, honoring configured `HTTP_PROXY`, `HTTPS_PROXY`, and `NO_PROXY` settings without exposing their values in reports.

```bash
pnpm run db:bootstrap:focused:dry-run
pnpm run research:queue:focused-literature:dry-run
pnpm --filter @metrev/database ingest:literature:openalex -- --query="MFC wastewater COD" --dryRun
pnpm --filter @metrev/database ingest:literature:crossref -- --query="MFC wastewater COD" --dryRun
pnpm --filter @metrev/database ingest:literature:europepmc -- --query="MFC wastewater COD" --dryRun
pnpm run metrev:doctor -- --json --probe-providers
```

They do not download papers, establish access rights, extract full text, deduplicate provider records, validate measurements, or create a reviewed evidence set. A real ingestion requires a deliberately configured database and provider access; use it only after reviewing the target database and the source/access policy. A 500-record target is not a claim that the literature is complete, representative, or scientifically validated.

It is based on the checked-in runtime and contracts rather than the number of model names in the catalog. The decision-support product needs trustworthy comparisons of wastewater treatment, MFC electricity, MEC hydrogen as a secondary output, biosensor behavior, and operating tradeoffs. A candidate paper can guide formulation, geometry, boundary choices, parameters, and provisional development tests before human review; it becomes an accepted decision input or an independent validation set only through the separate evidence gates.

For a spatial domain, a conservative formulation must connect local inventories and fluxes (for example, `∂(εC)/∂t + ∇·(uC − D_eff∇C − z(F/RT)D_eff C∇φ_l) = R_C`, with superficial velocity `u` and `D_eff = εD_free/τ`) with charge continuity (`∇·i_l = a_v j_F`, `∇·i_s = −a_v j_F`) and matched interface/boundary conditions. Here `a_v(x,y,z)` is accessible reactive area per bulk volume: porosity, tortuosity, material morphology, wetting and biofilm coverage affect it but porosity alone does not determine it. The signs, units, stoichiometry, geometry, constitutive laws and boundary values must be chosen for each system; this sketch is an implementation requirement, not an existing METREV equation or an experimental fit. The present restricted cell has no convection or locally solved electrode charge fields.

Source roles and limits are explicit. [Casula et al. (2022)](https://doi.org/10.1051/e3sconf/202233408005) give an open 3D MFC formulation and three anode geometries, but the published geometry and simulated fields are not a ready independent 3D METREV validation set. [Gadkari and Sadhukhan (2020)](https://doi.org/10.1038/s41598-020-65375-5) use 38 literature data sets for a dimensionless MFC correlation and warn that active area and porous-electrode geometry limit its transfer; their fitted aggregate is not a universal local-area law. [Moshtarikhah et al. (2017)](https://doi.org/10.1007/s10800-016-1017-2) motivate Nernst–Planck transport, Donnan interfaces and tortuosity-dependent effective diffusivity in a Nafion membrane; their reactor conditions are not interchangeable with MFC/MEC conditions. Gatti 2017, Zeng 2010, Picioreanu 2007/2010, Hamelers 2011, Pinto 2011 and Call/Logan 2008 are formulation or design leads already cited in the code and local source register; this inventory does not claim to have extracted all of their raw observations. The CORA [MEC catalyst dataset](https://doi.org/10.34810/DATA2866) is the only fully local raw numeric source extracted here.

`python3 packages/database/scripts/extract-cora-electrochem.py --check` reproduces the three CORA numeric artifacts from the pinned original CC0 ODS files without writing them. Current density has five complete 3,673-point traces plus all 3,169 measured pairs of a sixth trace with 504 absent cells; an unpaired `F3676` value has no time coordinate. LSV has six 3,001-point curves in A versus V vs Ag/AgCl. EIS has 290 native numeric pairs across eight columns; the secondary column shows `#NAME?` in its header, the frequency coordinate is absent, and the README catalyst descriptions conflict with some sheet headers. Signed values are retained. The README also describes acetate medium in the method but refers to acetone additions for its current-density figure. These unresolved source discrepancies prevent justified circuit fitting, inferred feed pulses, or full-cell validation. The machine-readable files retain exact worksheet locators and source SHA-256; missing values and unavailable variables are not fabricated.

`pnpm run evidence:export:development` creates a versioned local development benchmark under `test-results/development-benchmark/`: 39,540 observed CORA coordinate/value rows, 290 separately labeled CORA EIS pairs, 26 distinct aggregate/qualitative literature claims from three other study records, and a manifest with source/extract/registry SHA-256, licenses, provenance, study conditions, exclusions, and split. The aggregate claims retain their original reported value shapes and missing-condition reasons; they are not raw measurement pairs. The export does not interpolate the 504 absent cells, assign an EIS frequency, normalize current by unknown electrode area, or label any record as an independent validation set. The contract is `bioelectro-copilot-contracts/contracts/research/development-benchmark.schema.yaml`. More complete matched wastewater and full-cell studies remain required.

The next data acquisition needs separate matched study cases for MFC wastewater operation, MEC voltage/COD/H2 balance, porous-anode geometry and active surface, membrane ion flux, cathode polarization/gas, biosensor calibration and multi-cell stack scaling. Each record must include license, source span/table/cell, protocol, geometry, materials, feed/chemistry, circuit boundary, time or spatial coordinate, raw units, sample/replicate identity, measurement uncertainty where reported, extraction method and a declared development/calibration/independent role. A DOI or model paper may guide implementation immediately; absent experimental fields remain explicit blockers for the particular comparison, not for implementing and numerically verifying its equations.
