# Spatial boundary: current implementation

`spatial-input-v1` in `packages/domain-contracts/src/spatial-model-schema.ts` is a data contract. It validates source-backed geometry extents, physical region tags, oriented interfaces, referenced/generated meshes, material and species fields, initial and boundary conditions, circuit boundary and requested outputs. Constant, piecewise, sampled and artifact-backed fields have explicit representations. A valid payload is **not** a mesh, a PDE implementation or a successful run.

`resolvePhysicsComposition()` in `packages/electrochem-models/src/physics-composition.ts` is a shared API/UI capability resolver. It returns requested modules, unimplemented modules and configuration incompatibilities. The restricted 1D solver passes through the same resolver before execution. The persisted case runner handles 0D and a complete restricted 1D case in development status; `/api/modeling/coupled-cell-1d` remains a separate analyst calculation. Neither 2D nor 3D is executable. Unsupported selection never triggers a lower-dimensional fallback.

The source of scientific meaning is `bioelectrochem_agent_kit/domain/`; external schemas reside in `bioelectro-copilot-contracts/contracts/`. `spatial-parameter-authority.json` is the versioned authority for the currently supported spatial **material fields**. The TypeScript contract imports it directly to check parameter IDs, region kinds, dimensions, units and ranges; a governance check compares overlapping units with the component catalog. This is a subset, not an inventory of every PDE variable or boundary coefficient. The runtime contract needs a mirrored external schema and a variable/boundary-unit authority before full spatial case intake. The current box extents and region tags do not define subdomain geometry or produce physical groups. Boundary tags are references, not discretized boundary faces.

Before a 2D cell run, implement source-backed parameter authority, geometry/mesh generation with physical groups, conservative species/charge/flow/reaction equations, interface and circuit closure, numerical verification, async jobs, artifact storage, case runner, API/UI and reports. The complete sequence and gates are in `governance/ROADMAP.yaml` and its referenced 40-point source sections. Numerical convergence never promotes empirical maturity.

`spatial-sidecar-v1` adds a separate worker boundary for mesh generation and restricted development operations. `planar-layers-v1` specifies sourced widths, height, four outer boundary roles and ordered layer interfaces. The `planar_stokes` request binds the exact mesh recipe and selected mesh digest to a validated v2 input digest, one liquid region, source-backed constant viscosity and complete inlet/outlet traction. The `planar_darcy` request binds the same identities to one porous anode, biofilm or separator region, source-backed constant pore-fluid viscosity and intrinsic permeability, and pressures on opposing ports. `planar_darcy_transport` passes the computed Darcy velocity into a neutral passive scalar advection-diffusion solve on the same porous mesh, with source-backed effective diffusivity and concentration at matching pressure ports. The Python process deterministically rebuilds and hash-checks the selected mesh. Stokes solves EQ-FL-002; Darcy solves the homogeneous, isotropic EQ-FL-003 weak form with no-flow walls; the transport operation solves the zero-reaction, zero-migration EQ-SP-001 limit. These operations write pressure and x/y velocity, plus concentration for Darcy transport, as first-order Lagrange fields to XDMF/HDF5 and return flow/species balance diagnostics, convergence, field bindings, physical groups and artifact hashes. The Darcy-transport response also records nodal sample counts, extrema, area-weighted means and integrals with dimensional units, plus the direct PETSc method, iteration count and convergence reason for both linear solves. The explicit development-only Darcy worker adapter persists these field summaries and direct linear-solver outcomes in an input-bound result-v2 manifest through the owner-scoped local mesh and field stores. Nonlinear residual history remains marked not applicable because this operation runs direct linear solves only. The transport fixture does not imply bulk/porous coupling, biological kinetics, ionic migration or product solver admission. Fixture dimensions and values are test data, not cell parameters.

Result-v2 can retain direct linear-solver method, iteration count, status and termination data separately from nonlinear residual histories. Linear solves do not fabricate nonlinear residual samples; solver adapters must continue to report the appropriate convergence or not-applicable state for nonlinear execution.

`packages/spatial-worker/src/darcy-development-adapter.ts` is an opt-in executor module for local runs. Configure `METREV_SPATIAL_WORKER_EXECUTOR_MODULE` to its path and set `METREV_SPATIAL_SIDECAR_PYTHON`, `METREV_SPATIAL_SIDECAR_MODULE_DIR` and `METREV_SPATIAL_DEVELOPMENT_ARTIFACT_ROOT`; the latter must point to a private writable directory. This adapter accepts only one porous region, four scalar outputs and a neutral passive species. It does not register API admission, and the API remains fail-closed unless a separate development admission is explicitly injected. The sidecar process limit is at most 120 seconds.

Run the isolated fixture locally with Gmsh installed: `METREV_REQUIRE_GMSH=1 python3 -m unittest discover -s tests/contracts -p test_spatial_sidecar.py -v`. The normal test suite checks health and structured dependency failure when Gmsh is absent. CI installs pinned Gmsh for the real mesh gate. The Dockerfile is a pinned numerical environment candidate; its compatibility has not yet been verified here.

The mesh contract remains separate from legacy `spatial-input-v1`: no 2D cell case can be admitted solely because a mesh exists. The v1 box extents and region tags do not locate subdomains or assign physical boundary facets. The Stokes operation is a narrow research worker boundary; the product case runner, spatial job admission, durable artifact provider and API/UI do not invoke it. The local development mesh-artifact adapter is described in ADR-004; no production artifact provider is deployed.

`spatial-input-v2` now provides that **research data boundary** for the bounded planar geometry. It references a `msh4` manifest by URI and hash, matches every physical group/component/interface to ordered layers, and validates state domains, species properties, reaction stoichiometry, sampled field positions, circuit polarity and variable-specific boundary units from `spatial-variable-authority.json`. An exterior facet group crossing multiple layers can receive a condition only for a variable declared in all those layers. The external contract mirror is `bioelectro-copilot-contracts/contracts/spatial_input_v2.yaml`. The `spatial-input-v1` reader and existing persisted 0D cases are untouched. The v2 schema does not read an artifact or execute a PDE; storage authorization, source-specific scientific completeness and 1D/3D variants remain open.

An optional `vector_outputs` declaration composes a planar velocity view from separately declared `velocity_x` and `velocity_y` scalar states in a shared eligible domain. `requested_outputs` may name that view; input-bound v2 results must return a vector with matching unit and domains. Scalar metrics may derive from a named component's min/max/mean/integral, with the component axis, field, value and unit checked. No velocity field is solved or synthesized by this contract, and v1 result snapshots remain readable.

The optional `stokes_development` block admits a single bulk-liquid planar channel to the research input boundary under `EQ-FL-002`. It requires a source-traced constant dynamic viscosity material field, named pressure and x/y velocity states, exactly two no-slip walls, and explicit full x/y Cauchy traction `σ·n` with outward liquid normal at the inlet and outlet. Those values carry units and provenance and enter the weak-form right hand side with positive sign. It rejects porous or electrode regions and overlapping generic state boundary conditions; neither pressure-only traction nor a bulk↔porous interface is inferred. The block is development metadata only and does not route a run to a solver.

The v2 mesh reference retains the exact sidecar request. Parsing compares its complete recipe structurally with the declared case geometry and recomputes the normalized request SHA-256. The Node sidecar client builds a reference only when the response request ID and serialized input SHA-256 match that request. It can build restricted `planar_stokes`, `planar_darcy` and `planar_darcy_transport` requests from the v2 input; each operation verifies the regenerated selected mesh against its admitted digest and reports state-to-dataset bindings. `@metrev/spatial-artifact-store` adds local development adapters for meshes and fields, with owner-scoped reads; the authenticated spatial API serves verified field bytes. Product mesh authorization, durable production object storage, case-runner solver admission and persistence of these new solve outputs remain pending. The v2 contract alone still does not execute a PDE.

## Result state-field binding

`spatialSimulationResultForInputSchema` supplements standalone structural parsing with the immutable v2 input. Both direct and leased repository transitions validate completed and failed manifests against that input before writing: field variable or declared vector ID, canonical unit, eligible domains, shape, coordinate system and input hash/version must match. No implicit unit conversion or relabeling occurs. Existing state kinds remain scalar; only an explicitly composed planar x/y velocity output may be a vector field. Its component summaries and derived metrics are checked. Other vector quantities and independent scalar derivations remain open. Invalid result metadata leaves the run unchanged so a worker can record a structured failure without the invalid manifest.

The input-bound result check also requires the result mesh to retain the admitted mesh digest, geometry version, refinement level, generator version and exact physical-group tag-to-ID map. Each manifested region, exterior boundary and oriented interface must match that geometry, including component association and boundary/interface role. Returned state fields must include every requested variable and may not add unrequested variables. Structural result parsing alone cannot establish these input-specific mappings.

The input digest is computed at run admission. PostgreSQL JSONB may reorder keys in the stored snapshot, so result validation uses the admitted digest retained on the run and checks the parsed snapshot for variable meaning. It does not recalculate an order-dependent JSON digest from the reloaded snapshot. Existing runs and hashes retain their original identity.

# Development field artifacts

`LocalSpatialFieldArtifactStore` accepts a schema-checked field manifest, verifies the source file against its declared SHA-256 and byte length, and persists immutable bytes plus a checksummed owner/run/field manifest in a private filesystem root. Reads require the matching owner, run, field, URI and dataset path; the authenticated API independently verifies the bytes before streaming. This adapter is for local development and does not admit a spatial solver or supply durable production object storage.
